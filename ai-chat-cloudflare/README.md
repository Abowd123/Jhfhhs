# AI Chat App — نسخة Cloudflare Pages (+ إدارة مفاتيح API متعددة)

نفس الموقع بالضبط، لكن بدل Netlify Edge Functions، بيشتغل كـ **Cloudflare Pages Function** — استضافة مجانية دائمة، وبتدعم رفع مباشر بالسحب والإفلات **مع** كود السيرفر (بعكس Netlify Drop).

## ✨ الميزة الجديدة: إدارة مفاتيح API من داخل الموقع

دلوقتي فيه صفحة إعدادات (زر ⚙️ في القائمة الجانبية) تقدر منها:
- تضيف **أكثر من مفتاح API** (حتى لو من مزودين مختلفين طالما الرابط بصيغة OpenAI-compatible)
- تفعّل/تعطّل أي مفتاح
- تضغط **"اختبار جميع المفاتيح"** فيبعتلك حالة كل مفتاح (يعمل ✅ / لا يعمل ❌ مع سبب الفشل)
- تختار وضع التشغيل:
  - **تلقائي (Failover)**: الموقع يجرب المفاتيح المفعّلة بالترتيب، ولو واحد فشل (401/429/انقطاع) ينتقل للتالي تلقائيًا من غير ما المستخدم يحس
  - **يدوي**: تحدد مفتاح بعينه يُستخدم دايمًا

المفاتيح بتتخزن **على السيرفر فقط** (عبر Cloudflare KV)، ومحمية بكلمة مرور إدارة، ومفيش أي مفتاح كامل بيوصل للفرونت إند أبدًا (بيتعرض بشكل مموّه زي `sk-a****...ab12`).

## بنية المشروع

```
ai-chat-cloudflare/
├── functions/
│   ├── _lib/
│   │   ├── auth.js         ← التحقق من صلاحية جلسة الأدمن
│   │   └── store.js        ← قراءة/حفظ قائمة المفاتيح في KV
│   └── api/
│       ├── chat.js         ← نقطة الشات (تدعم عدة مفاتيح + Failover)
│       └── admin/
│           ├── login.js    ← تسجيل دخول الإدارة
│           ├── keys.js     ← إضافة/عرض/تعديل/حذف المفاتيح
│           └── test.js     ← اختبار كل المفاتيح دفعة واحدة
├── public/                   ← الفرونت إند (يُنشر كما هو)
│   ├── index.html
│   ├── css/style.css
│   └── js/
│       ├── app.js
│       └── settings.js     ← منطق نافذة الإعدادات
└── README.md
```

Cloudflare بيربط تلقائيًا أي ملف داخل `functions/` بمسار مطابق لمكانه (الملفات والمجلدات اللي بادئتها `_` بتتجاهل من الراوتنج وتستخدم كموديولز مشتركة فقط)، فمفيش أي إعداد يدوي للمسارات مطلوب.

## ⚙️ خطوات الإعداد الإضافية (إجبارية لتفعيل الميزة الجديدة)

### 1. إنشاء KV Namespace
من لوحة Cloudflare:
`Workers & Pages` → `KV` → `Create a namespace` → سمّها مثلاً `CHAT_KV`

### 2. ربط الـ KV بمشروع الـ Pages
من صفحة مشروعك:
`Settings` → `Functions` → `KV namespace bindings` → `Add binding`
- Variable name: `CHAT_KV` (لازم يكون بالظبط بهذا الاسم، لأنه ده اللي الكود بيستخدمه)
- KV namespace: اختر اللي أنشأته

### 3. تعيين كلمة مرور الإدارة
`Settings` → `Environment variables` → `Add variable`
- Variable name: `ADMIN_PASSWORD`
- Value: كلمة مرور قوية من اختيارك (هتستخدمها لفتح صفحة الإعدادات)
- **مهم:** فعّلها كـ Secret (Encrypt) لو الخيار متاح

### 4. (اختياري) الإبقاء على المفتاح القديم كخيار احتياطي
لو عندك `GOROUTER_API_KEY` متعيّن من قبل، هيفضل شغال تلقائيًا كمفتاح افتراضي **لحد ما تضيف أول مفتاح من صفحة الإعدادات** — بعدها المفاتيح المضافة من الموقع هي اللي هتُستخدم.

### 5. إعادة النشر
بعد إضافة الـ binding والمتغير، لازم تعمل **Retry deployment** (أو ارفع نسخة جديدة) عشان التغييرات تتفعّل.

## استخدام صفحة الإعدادات

1. افتح الموقع → اضغط **⚙️ إعدادات مفاتيح API** في القائمة الجانبية
2. أدخل كلمة مرور الإدارة (`ADMIN_PASSWORD`)
3. أضف مفتاح API: اسم مميز + رابط الـ API (افتراضيًا `https://gorouter.app/v1/chat/completions`) + المفتاح نفسه + اسم الموديل
4. كرر الخطوة لأي عدد من المفاتيح
5. اضغط **"اختبار جميع المفاتيح"** للتأكد إن كل واحد شغال فعليًا
6. اختر وضع التشغيل (تلقائي أو مفتاح محدد) من القائمة المنسدلة بالأعلى

كل التعديلات بتتحفظ فورًا على السيرفر (KV)، ووضع التشغيل بيتحفظ محليًا في متصفحك.

## الطريقة 1: النشر عبر الموقع مباشرة (الأسهل، فيها رفع بالسحب والإفلات)

### 1. أنشئ حساب مجاني
اذهب إلى https://dash.cloudflare.com وسجّل حساب (مجاني).

### 2. من القائمة الجانبية
اختر **Workers & Pages** ← **Create** ← تبويب **Pages** ← **Upload assets** (أو "Direct Upload").

### 3. ارفع مجلد المشروع
اسحب وأفلت **كل مجلد `ai-chat-cloudflare`** (وليس مجلد `public` فقط) — Cloudflare هيتعرف تلقائيًا على مجلد `functions/` ويفعّل الـ Function، ومجلد `public/` هيتنشر كموقع ثابت.

> ملاحظة: بعض واجهات الرفع بتطلب تحديد "Build output directory" = `public`. اتبع التعليمات الظاهرة في الشاشة وقت الرفع.

### 4. أضف مفتاح الـ API (خطوة إجبارية)
بعد إنشاء المشروع:
`Settings` → `Environment variables` → `Add variable`
- Variable name: `GOROUTER_API_KEY`
- Value: مفتاحك الحقيقي
- طبّقها على بيئة **Production** (و Preview لو حبيت)

ثم اعمل **Retry deployment** أو ارفع نسخة جديدة عشان يتفعّل المتغيّر.

### 5. الرابط النهائي
هتحصل على رابط دائم ومجاني زي:
`https://your-project-name.pages.dev`

## الطريقة 2: عبر Wrangler CLI (بديل، لو حبيت التحكم من التيرمينال)

```bash
npm install -g wrangler
wrangler login
cd ai-chat-cloudflare
wrangler pages deploy public --project-name=ai-chat-app
wrangler pages secret put GOROUTER_API_KEY --project-name=ai-chat-app
```
(الأمر الأخير هيطلب منك تكتب المفتاح، ولازم تعمل deploy تاني بعدها عشان يتفعّل).

## اختبار سريع بعد النشر

```bash
curl -X POST https://your-project-name.pages.dev/api/chat \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"مرحباً"}],"model":"claude-opus-5-thinking"}'
```

يجب أن يرجع لك رد على شكل SSE (أسطر تبدأ بـ `data: `).

## ملاحظات مهمة
- مفتاح الـ API لا يظهر أبدًا في كود الفرونت إند، فقط داخل الـ Function على السيرفر (مخفي تمامًا عن المتصفح).
- Cloudflare Pages مجاني بشكل دائم لهذا النوع من المشاريع الصغيرة، وبدون "Sleep" أو توقف بعد فترة خمول (بعكس Render Free).
- أي تعديل لاحق: ارفع المجلد تاني (Direct Upload) أو اعمل `wrangler pages deploy public` تاني.
